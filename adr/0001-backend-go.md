# ADR-0001: Backend использует Go

- **Статус:** Принято
- **Область:** Бэкенд (`backend/`)
- **Дата:** 2026-10-25
- **Заменяет:** —
- **Заменён:** —

## Контекст

Проект состоит из двух изолированных частей: серверной (`backend/`) и клиентской (`frontend/`). Для серверной части нужно зафиксировать язык реализации, чтобы все будущие change, спеки и задачи исходили из одного технологического решения и не пересматривали его на уровне отдельных задач.

Клиентская часть остаётся на TypeScript + React (см. `README.md`); этот ADR её не касается.

## Решение

**Обязательное правило: вся серверная логика проекта (`backend/`) пишется на Go.**

- Никакой другой язык не используется для кода в `backend/`.
- Минимальная версия тулчейна — Go 1.27 (см. `go.mod` и `README.md`).
- Реализация на стандартной библиотеке; сторонние зависимости и фреймворки добавляются только при необходимости (см. `AGENTS.md` — Конвенции).
- Правило обязательно для всех спецификаций (`openspec/specs/`), change-артефактов и реализации; артефакты, предполагающие другой язык для `backend/`, недопустимы.

## Последствия

- Проще: единый тулчейн и конвенции серверной части; сборка и запуск стандартными командами Go (`go build ./...`, `go run .`).
- Сложнее: выбор технологий, не имеющих зрелых Go-библиотек, потребует обходных решений или пересмотра решения.
- Пересмотр: решение можно изменить только новым ADR, который заменяет этот (старый файл не меняется); изменение поведения, вытекающее из нового решения, оформляется через change-процесс OpenSpec.
