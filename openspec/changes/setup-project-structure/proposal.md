# Proposal: настройка структуры проекта (backend + frontend)

## Why

Проект находится в стартовом состоянии: в репозитории нет кода приложения. Прежде чем начинать разработку функциональности, нужно зафиксировать базовую организацию репозитория — два изолированных приложения (`backend/` и `frontend/`) с минимальными рабочими скелетами, чтобы любая новая работа сразу ложалась в понятную структуру.

## What Changes

- Создаются две отдельные папки верхнего уровня:
  - `backend/` — серверная логика на Go (минимальный рабочий скелет: `go.mod`, `main.go` с простым HTTP-эндпоинтом здоровья);
  - `frontend/` — клиент на TypeScript + React (минимальное рабочее приложение на Vite).
- Добавляются корневые файлы общего назначения: `README.md` (описание структуры и команд запуска) и `.gitignore` (артефакты Go и Node).
- Каждая папка самодостаточна: собственный набор зависимостей и собственные команды сборки/запуска, без общей сборки через корень.
- Стек зафиксирован как текущее решение, а не догма: структура спроектирована так, чтобы Go и React можно было позже заменить без переделки топ-левел организации.

Отсутствует (breaking changes нет): проект зелёный, существующего кода и API нет.

## Capabilities

### New Capabilities

- `project-layout`: соглашение о структуре репозитория — обязательные каталоги верхнего уровня `backend/` и `frontend/`, их самодостаточность и правила размещения общих корневых файлов.
- `backend-app`: минимальный независимо собираемый и запускаемый Go-сервис в `backend/`, отвечающий по HTTP и готовый к наращиванию серверной логики.
- `frontend-app`: минимальное независимо собираемое и запускаемое React + TypeScript приложение в `frontend/`, отображающее стартовую страницу.

### Modified Capabilities

_(нет — существующих спецификаций в проекте нет)_

## Impact

- **Код**: новые каталоги `backend/` и `frontend/` с минимальными скелетами; существующий код не затрагивается.
- **Зависимости**: backend — модуль Go (только стандартная библиотека); frontend — Node.js-проект с Vite, React, TypeScript (dev- и runtime-зависимости npm).
- **Инструменты**: для работы требуются Go и Node.js + npm; никаких настроек CI, Docker или контрактов API на этом этапе не предполагается (осознанно вне объёма).
- **Системы**: влияние на внешние системы отсутствует; HTTP-эндпоинт backend слушает только локально и служит проверкой работоспособности.
