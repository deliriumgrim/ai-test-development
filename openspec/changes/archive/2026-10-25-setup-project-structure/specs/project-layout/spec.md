# Spec Delta: project-layout

## Purpose

Определяет постоянную организацию репозитория приложения: изолированные каталоги верхнего уровня для серверной и клиентской частей и правила размещения общих файлов. Организация survives замену технологического стека.

## ADDED Requirements

### Requirement: Два каталога верхнего уровня

Репозиторий SHALL содержать ровно два каталога верхнего уровня для кода приложения: `backend/` для серверной логики и `frontend/` для клиентского кода. Весь серверный код MUST находиться в `backend/`, весь клиентский код — в `frontend/`.

#### Scenario: Новые файлы ложатся в структуру

- **WHEN** разработчик добавляет новый серверный или клиентский файл
- **THEN** он размещается внутри `backend/` или `frontend/` соответственно, и ни один файл кода приложения не появляется вне этих каталогов

### Requirement: Самодостаточность каждой части

Каталоги `backend/` и `frontend/` MUST быть самодостаточными: каждая часть владеет собственными зависимостями и собственными командами сборки и запуска, исполняемыми из каталога части. Сборка или запуск одной части MUST NOT требовать сборки или установки зависимостей другой части.

#### Scenario: Независимая работа с backend

- **WHEN** разработчик работает только над серверной частью
- **THEN** все команды сборки и запуска backend выполняются внутри `backend/` без обращения к `frontend/`

#### Scenario: Независимая работа с frontend

- **WHEN** разработчик работает только над клиентской частью
- **THEN** все команды установки зависимостей, сборки и запуска frontend выполняются внутри `frontend/` без обращения к `backend/`

### Requirement: Корневые файлы общего назначения

В корне репозитория SHALL находиться только описание проекта и общесистемные файлы (`README.md`, `.gitignore`), относящиеся к проекту в целом. Корневые файлы MUST NOT содержать код или конфигурацию, относящуюся только к одной из частей.

#### Scenario: Просмотр корня репозитория

- **WHEN** новый разработчик открывает корень репозитория
- **THEN** он видит описание структуры и команд запуска в `README.md`, и ни один корневой файл не дублирует настройки backend или frontend
