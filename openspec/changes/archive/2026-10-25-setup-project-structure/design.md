# Design

## Context

Репозиторий пуст (только `openspec/`): кода, инструментов сборки и CI нет. См. proposal.md — Why. Пользователь выбрал объём «минимальные рабочие скелеты»: каждая часть запускается сразу, но без Docker, CI, монорепо-тулинга и контрактов API. Стек (Go / TypeScript + React) зафиксирован как текущее решение и может смениться в будущем — это ключевое ограничение на проектирование.

## Goals / Non-Goals

**Goals:**

- Два самодостаточных каталога верхнего уровня, готовых к коммиту и запуску.
- Минимум зависимостей и генерируемых файлов: убрать всё лишнее из шаблонов.
- Независимость структуры от конкретного стека: замена Go или React не должна ломать топ-левел организацию.

**Non-Goals:**

- Монорепо-инструменты (npm workspaces, Nx, go.work) и общая корневая оркестрация сборки.
- Docker, CI/CD, линтеры, тестовые фреймворки.
- Реальное взаимодействие backend ↔ frontend (прокси, контракты API, CORS).
- Бизнес-логика: пока только скелеты с проверкой работоспособности.

## Decisions

1. **Две папки без монорепо-тулинга.** Каждая часть — самостоятельный проект со своими зависимостями и командами; корень не собирает ничего.
   *Альтернативы*: npm workspaces / Nx — отвергнуты: для двух изолированных приложений на разных стеках они добавляют связность и усложняют будущую замену стека.

2. **Backend: чистый `net/http`, без фреймворка.** `go.mod` (имя модуля `app/backend` — нейтральное, до появления удалённого репозитория), `main.go` с `http.Server`, эндпоинт `GET /healthz` → `200 OK`. Порт — из переменной окружения `PORT`, по умолчанию `8080`.
   *Альтернативы*: chi/gin/echo — отвергнуты: для health-скелета зависимости не нужны; фреймворк добавляется одной зависимостью, когда появится реальная логика.

3. **Frontend: Vite + React + TypeScript (шаблон `react-ts`).** Vite — фактический стандарт скаффолдинга React+TS; create-react-app устарел, Next.js избыточен для клиентского SPA-скелета.
   *Альтернативы*: CRA — deprecated; Next.js/Remix — серверный рендеринг не нужен на этом этапе.

4. **Чистка шаблона Vite до минимума.** Удалить демо-контент (логотипы, счётчики, дефолтные стили); оставить точку входа (`main.tsx`), корневой компонент (`App.tsx`) со стартовой страницей и минимальную конфигурацию.

5. **Один корневой `.gitignore` с секциями Go и Node.** Проще сопровождать, чем файлы в каждой папке; самодостаточность (требование `project-layout`) касается сборки и запуска, а не git.
   *Альтернатива*: `.gitignore` в каждой папке — пересмотрится, если части вынесутся в отдельные репозитории.

6. **Корневой `README.md`** — схема каталогов, требуемые версии инструментов и команды запуска каждой части; единственная точка входа для нового разработчика.

## Risks / Trade-offs

- [Шаблоны Vite и `go mod init` генерируют лишние файлы] → в tasks.md предусмотрен явный шаг чистки и ревью итогового дерева до коммита.
- [Разные версии Go/Node у разработчиков] → зафиксировать минимальную версию в `go.mod` и в README; `engines` в `package.json` — по желанию позже.
- [Порт 8080 может быть занят] → порт переопределяется переменной `PORT` без изменения кода.
- [«Пока так» по стеку соблазняет перегрузить структуру абстракциями] → осознанно нет: спецификации формулируют поведение, а не фреймворки, так что замена стека меняет содержимое папок, но не контракты `project-layout`.

## Migration Plan

Не применимо (greenfield). Откат — удаление созданных файлов и каталогов `backend/`, `frontend/`, корневых `README.md` и `.gitignore`.
