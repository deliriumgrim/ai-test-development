# backend-app Specification

## Purpose

Минимальный независимо запускаемый Go-сервис в `backend/`: точка входа серверной логики, который собирается и отвечает по HTTP, подтверждая работоспособность.

## Requirements

### Requirement: Серверная логика на Go

Серверная часть SHALL быть реализована на Go и оформлена как самостоятельный Go-модуль внутри `backend/` с файлом `go.mod` и точкой входа `main.go`.

#### Scenario: Проверка стека backend

- **WHEN** разработчик открывает `backend/`
- **THEN** он видит валидный Go-модуль (`go.mod`) и исходный код на Go, собираемый стандартным тулчейном

### Requirement: HTTP-эндпоинт проверки работоспособности

Сервис SHALL слушать HTTP-запросы и на запрос проверки работоспособности (`GET /healthz`) отвечать статусом `200 OK`, подтверждая, что сервис жив. Порт SHALL задаваться настройками запуска и иметь значение по умолчанию для локальной разработки.

#### Scenario: Успешный запрос health check

- **WHEN** сервис запущен и клиент выполняет `GET /healthz`
- **THEN** сервис отвечает статусом `200 OK`

### Requirement: Независимая сборка backend

Проект в `backend/` SHALL собираться командой `go build ./...` без ошибок при наличии только тулчейна Go и содержимого каталога `backend/`.

#### Scenario: Чистая сборка с нуля

- **WHEN** разработчик выполняет `go build ./...` внутри `backend/` на машине, где этот каталог собран впервые
- **THEN** компиляция завершается успешно без ошибок

### Requirement: Независимый запуск backend

Сервис SHALL запускаться командой `go run .` из каталога `backend/` и после старта отвечать на запрос проверки работоспособности.

#### Scenario: Локальный запуск и проверка

- **WHEN** разработчик выполняет `go run .` в `backend/` и отправляет запрос проверки работоспособности
- **THEN** сервис запускается и отвечает `200 OK`
